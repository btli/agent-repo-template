# Project charter

## Mission

Maintain a reliable project and make its supported workflows clear to contributors.

## In scope

- Defects and improvements in documented project behavior.
- Compatibility, tests, and documentation for supported interfaces.

## Out of scope

- Requests that do not relate to this project.
- Private security details in public issues.

## Priorities

- P0: Data loss, a security incident, or a complete service outage.
- P1: A core workflow is unusable for many users.
- P2: A limited defect has a practical workaround.
- P3: Cosmetic polish or a small convenience.

## A good report includes

- Steps to reproduce and the behavior you expected.
- Relevant versions, logs, and a minimal example.

## Support policy

Use the repository's private security reporting process for vulnerabilities. Public issue
reports should omit credentials and private data.
